Notes vault setup

This file lives outside docs/ and is never published. It runs entirely in your browser — nothing is sent anywhere. Everything you type here is a secret; close the tab when you are done, and never paste the token or passphrase into the deployed page or into a chat.

crypto.subtle is unavailable — this browser does not treat the page as a secure context. Serve the folder locally instead: python3 -m http.server, then open http://localhost:8000/notes-setup.html.

Order of operations

  1. Create the GitHub token (see the bottom of this page).
  2. Create a secret gist with one file called notes.json and any placeholder content. Copy its ID out of the URL.
  3. Run Create a new vault below.
  4. Paste the CONFIG block into docs/notes/notes.js, replacing the empty one.
  5. Paste the initial gist content into the gist, replacing the placeholder.
  6. Commit and push. Only the ciphertext is committed.

Creating the GitHub token



	Try a fine-grained token first: Settings → Developer settings → Personal
	access tokens → Fine-grained tokens, expiration No expiration,
	and under Account permissions set Gists to
	Read and write. No repository access is needed.




	Then verify it actually works, because fine-grained token support for the
	gists API has historically been unreliable:



curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/gists



	If that is not 200, fall back to a classic token with
	the single gist scope ticked and nothing else, expiration
	No expiration. That scope grants access to your gists only.
